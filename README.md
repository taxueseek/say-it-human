# Say It Human

> 你的文字，被 AI 污染了吗？

当读者一眼看出这是 AI 写的，你的内容就已经输了。

**Say It Human** 是一套 AI 味检测与消除工具。覆盖 2026 年最新 AI 味特征：过度拔高、否定式煽情、虚假范围、翻译腔、平台套路、RLHF 模板化等。可在 Claude Code、Codex、Cursor、Windsurf 等任意支持 skill / system prompt 的 Agent 上使用。

最新更新：**v1.1.0**

**v1.1.0 更新**：AI 味检测引擎大升级 —— 从 5 类基础问题升级为 **12 维来源图谱**（2026 版），覆盖结构对称、概括泛滥、情绪空洞、句式整齐、细节缺失、语气权威、过度拔高、否定式煽情、虚假范围、翻译腔、平台套路、RLHF 模板化。新增 AI 味浓度分级（轻微/中等/严重/致命）和完整诊断报告模板，定位到具体句子，直接输出改写版本。新增「改稿手」skill，处理人写但被套话淹没的内容。

**v1.0.0**：首发。两个核心 skill：去 AI 味（humanize-ai）处理 AI 生成内容，改稿手（editor-revisor）处理人写但被套话淹没的内容。

作者：taxueseek

所有内容开放，可以整套装，也可以只拿一部分。示例、方法论、检测清单，都能单独用。

## 去 AI 味（humanize-ai）

**核心原则**：看密度，不看出现。

对仗、排比、成语，真人写作里本来就在用。光是用了这些不算 AI 腔；**反复堆叠、跟前后内容没关系、换到别的话题上也成立**，这才是。

**判断标准**：
- 单次出现 → 不算
- 200 字内反复出现 3 次以上 → 算
- 整篇风格单调、缺乏变化 → 算

**唯一边界**：只用原文素材，不编人物、不造故事、不加细节。这条是底线，违反了就是在造假。

### 12 维 AI 味来源图谱（2026 版）

| 来源 | 识别信号 | 修法 |
|------|---------|------|
| **结构过于对称** | 三段式排比、段落长度一致、每段都有总结句 | 打破对称，长短不一，取消总结句 |
| **概括性语言太多** | 「总的来说」「综上所述」、抽象词替代具体场景 | 用具体时间/数字/人物替代 |
| **情绪词空洞** | 「令人深思」「至关重要」「意义深远」 | 删掉情绪词，换成引发情绪的具体细节 |
| **句式过于整齐** | 「不仅…而且…」、句子长度一致、规范动词 | 主动打断句式，换口语表达 |
| **缺乏具体细节** | 没有时间地点人物、「研究表明」不说哪项研究 | 加上时间、数字、具体人物 |
| **语气过于中性/权威** | 整篇没有一处「我不确定」、像教科书 | 加入真实的不确定、偏见、犹豫 |
| **过度拔高** ⭐新增 | 「历史性时刻」「分水岭」「里程碑」 | 保留事物本来大小，不强行赋予意义 |
| **否定式煽情** ⭐新增 | 「不仅仅是一双跑鞋，而是对自律的承诺」 | 直接说事实，删掉「不仅仅」 |
| **虚假范围** ⭐新增 | 「从 X 到 Y」硬凑、「涵盖多个领域」只沾边 | 删掉范围词，直接说做了什么 |
| **翻译腔** ⭐新增 | 「这一现象可以被解释为」、被动语态过多 | 被动改主动，中英混杂加解释 |
| **平台文体套路** ⭐新增 | 小红书体「绝绝子」、抖音体「家人们」全套照搬 | 像那个平台的人，但不像模板 |
| **RLHF 模板化** ⭐新增 | 虚词密度异常、句子长度方差过低、完美流畅感 | 故意打断流畅，加入「错误」和停顿 |

### AI 味浓度判断

| 浓度 | 表现 | 处理建议 |
|-----|-----|---------|
| 轻微 | 1-2 处来源，整体有人味 | 局部修改即可 |
| 中等 | 3-4 处来源，读者能感觉到但不确定 | 重点段落重写 |
| 严重 | 5-6 处来源，整篇感觉像模板生成 | 建议整体重写，保留核心观点 |
| 致命 | 结构+语言+细节全部是 AI 模式 | 建议从头想清楚要说什么 |

### 诊断 + 改写流程

1. **逐段扫描**：按 12 个来源逐项检查
2. **密度检测**：200 字内出现频率
3. **输出诊断报告**：定位、密度、原文、改法
4. **输出改写版本**：保留核心观点，直接输出完整改写文本

## 改稿手（editor-revisor）

**核心目标**：改完之后，这篇文章里要有一个真实的人在说一件真实的事。

### 动笔前判断三件事

1. **这个人是谁？**（管理者、技术人员、普通职场人？）
2. **他在跟谁说话？**（内部汇报、对外发布、说服某个人？）
3. **剥掉所有修饰，他真正要说的是哪几句？**

### 改稿决策表

| 情况 | 处理方式 |
|------|----------|
| 意思在，但被套话埋住了 | **大改** —— 挖出来 |
| 意思在，但表达方式不像这个人 | **轻改** —— 调整表达 |
| 找不到真实的人在说一件真实的事 | **不改** —— 反问并给方向 |
| 整篇就是仪式性文件 | **不挖真话** —— 只做清理 |
| 本来就是他会说的话 | **不动** |

### 什么该砍

- **套话开头**：在当今…、随着…的发展
- **程度虚词**：至关重要、不可或缺、显著提升
- **虚假对仗**：不是 A 而是 B——凑出来衬托的砍
- **口号收尾**：让我们共同…、未来可期
- **强行清单**：首先…其次…此外…最终

### 节奏原则

真人写东西不是每句都在发力。有时说完再补一句，有时自我修正。允许有松的地方，不要把每句都改成金句。

## 改写示例

### 去 AI 味示例

**输入**：
```
坐落于繁华都市的一隅，这家独立书店以其独特的选书品味和温馨的阅读氛围，成为城市文化爱好者的精神栖息地。我们致力于为每一位读者提供沉浸式的阅读体验，让知识与生活完美交融。
```

**输出**：
```
这家店藏在巷子深处，门面不大，但书选得很有意思。老板是个退休的中学语文老师，每周三下午会在店里给人讲古诗。来的人不多，但都是常客。
```

### 改稿手示例

**输入**：
```
本周在各位同事的通力协作下，项目取得了阶段性进展。我们克服了诸多困难，按计划完成了核心功能的开发工作。同时，我们也清醒地认识到存在的不足，将在后续工作中持续改进。
```

**输出**：
```
这周干了三件事：
- 用户登录模块做完，测了没大问题
- 支付接口对接遇到坑，对方的文档写得不清楚，耽误了一天
- 周五开了评审会，产品经理又改了需求

下周重点：把支付流程跑通，争取提测。
```

更多示例见 [`examples/`](examples/) 目录：
- [`marketing.md`](examples/marketing.md) — 营销文案改写
- [`academic.md`](examples/academic.md) — 学术/技术文本改写
- [`work.md`](examples/work.md) — 工作文档改写

## 知识库

Say It Human 的方法论是完全开放的。你不需要安装整套 Skill 才能用——可以只拿走你需要的部分。

### 场景 1：给你的 AI 加去 AI 味能力

把 `skills/humanize-ai/SKILL.md` 的内容粘贴到你的 system prompt 里。你的 AI 就有了 12 维检测 + 改写能力。

### 场景 2：做内容审核工具

用 12 维来源图谱作为检测清单，批量扫描内容库的 AI 味浓度。

### 场景 3：学习和研究

按 12 个来源维度分类，只研究你感兴趣的领域。比如只关注「平台文体套路」或「RLHF 模板化」。
