# 五场景规则详解

---

## 场景A：技术文档

### 核心原则
准确先于修辞，清晰先于热闹。

### 写作规则
| 规则 | 说明 |
|------|------|
| 一义一段 | 一个段落一个主要信息点 |
| 一义一句 | 一个句子一个清晰主干 |
| 机器可读保护 | 不动代码/URL/API路径 |
| 项目约定优先 | 先检查AGENTS.md/术语表 |

### 内容类型处理
| 类型 | 首段回答 |
|------|---------|
| 入口页/介绍页 | 覆盖什么、适合谁、从哪里开始读 |
| API文档 | 方法/路径/参数类型+单位+默认值+限制 |
| 界面文案 | 按钮说明动作+目标，错误提示说明影响+恢复 |
| 操作手册 | 前置条件+步骤+失败处理+恢复方式 |

### 禁止词
赋能、抓手、闭环、沉淀、对齐、对标、拉通、打通、洞察、赛道、调性、战役、势能、兜底、落盘、收口、透传

## 场景B：广告文案

### 核心框架
AIDA：注意→兴趣→欲望→行动

### 标题八公式
| 公式 | 结构 |
|------|------|
| 判断型 | 主题+关键节点 |
| 承诺型 | 人群+结果+方法 |
| 叙事型 | 一个/十年+人群+经历 |
| 痛点型 | 不想/不懂+痛点+方案 |
| 反直觉型 | 反常识+为什么 |
| 数据型 | 具体数字+结论 |
| 悬念型 | 有画面感的事件+悬念 |
| 对比型 | A vs B+选择 |

### 标题forbid-list
再论、浅谈、也谈、关于……的思考、……之我见

## 场景C：PPT演示

### 设计铁律
| 铁律 | 说明 |
|------|------|
| 一页一论点 | 每页只有一个核心信息 |
| 视觉层次 | 一个主色(60-70%)+1-2辅色+一个强调色 |
| 三明治结构 | 深色标题+浅色内容+深色结尾 |
| 图>表>文字 | 能用图不用表，能用表不用文字 |
| 留白呼吸 | 每页≤6行，每行≤20字 |

### 配色方案
| 主题 | 主色 | 辅色 | 强调 |
|------|------|------|------|
| 商务汇报 | 藏青 | 冰蓝 | 白色 |
| 创业融资 | 深绿 | 苔藓灰 | 米白 |
| 产品发布 | 珊瑚红 | 金色 | 藏青 |
| 技术分享 | 炭灰 | 白炭 | 纯黑 |

## 场景D：社交媒体

### 平台适配矩阵
| 维度 | 小红书 | 公众号 | 知乎 | 抖音 | 即刻 |
|------|--------|--------|------|------|------|
| 字数 | 300-800 | 1500-3000 | 800-5000 | 300-600 | 200-500 |
| 标题 | 关键词前置+emoji | 完整句子 | 疑问句 | 吸引眼球 | 短句+标签 |
| 段落 | ≤3行 | 2-4句 | 可长可分节 | 短句为主 | 碎片化 |
| 语气 | 亲切聊天 | 真诚有判断 | 专业有逻辑 | 强烈口语 | 洞见吐槽 |

## 场景E：Release Notes

### 核心原则
用户可见变化导向，从git log提取。

### 结构模板
```markdown
## Breaking Changes
## New Features
## Fixes & Improvements
## Deprecations
```

### 内容规则
| 规则 | 说明 |
|------|------|
| 按用户可见特征分组 | 不按内部功能分组 |
| 从git log提取 | 不从记忆写 |
| 一句一变化 | 不堆砌 |
| 双语结构 | 英文块+中文块并列 |

### 禁止
- "Polish" / "细节打磨" / "Misc improvements"
- 从记忆写
- 一句话包含多个变化
