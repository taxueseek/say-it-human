# 场景适配（Scene Fit）

> 不是改写得好不好，是改写得对不对——对不对这个平台、这个渠道、这个场景。

---

## 五场景规则矩阵

### 场景A：技术文档

**来源**：Tech-Doc-Style-Chinese（Fenng）

**核心原则**：准确先于修辞，清晰先于热闹。

**写作规则**：
| 规则 | 说明 | 示例 |
|------|------|------|
| 一义一段 | 一个段落一个主要信息点 | 不堆砌 |
| 一义一句 | 一个句子一个清晰主干 | 不连续堆叠条件 |
| 机器可读保护 | 不动代码/URL/API路径 | 原样保留 |
| 项目约定优先 | 先检查AGENTS.md/术语表 | 不机械替换 |
| 受众适配 | 开发者/实施/产品/运维不同 | 调整深度 |

**内容类型处理**：

| 类型 | 首段回答 |
|------|---------|
| 入口页/介绍页 | 覆盖什么、适合谁、从哪里开始读 |
| API文档 | 方法/路径/参数类型+单位+默认值+限制 |
| 界面文案 | 按钮说明动作+目标，错误提示说明影响+恢复 |
| 操作手册 | 前置条件+步骤+失败处理+恢复方式 |

**禁止词**：赋能、抓手、闭环、沉淀、对齐、对标、拉通、打通、洞察、赛道、调性、战役、势能、兜底、落盘、收口、透传

### 场景B：广告文案

**来源**：viral-content-machine

**核心框架**：AIDA（注意→兴趣→欲望→行动）

**标题八公式**：

| 公式 | 结构 | 示例 |
|------|------|------|
| 判断型 | 主题+关键节点 | "2026年，资产配置的分水岭" |
| 承诺型 | 人群+结果+方法 | "新手也能跑赢通胀的3个策略" |
| 叙事型 | 一个/十年+人群+经历 | "一个散户的十年" |
| 痛点型 | 不想/不懂+痛点+方案 | "不想再被割韭菜？先看这个" |
| 反直觉型 | 反常识+为什么 | "买基金的人，都挺能忍" |
| 数据型 | 具体数字+结论 | "A股单日成交3.6万亿" |
| 悬念型 | 有画面感的事件+悬念 | "那个凌晨三点还在看K线的人" |
| 对比型 | A vs B+选择 | "定投三年vs追涨杀跌" |

**标题 forbid-list**：再论、浅谈、也谈、关于……的思考、……之我见

**正文结构**：
```
开头3秒：制造好奇或共鸣
中段：价值证明（数据/故事/类比）
结尾：行动号召（明确动词+低门槛）
```

**CTA设计**：
- ✅ "好了，去试试"
- ✅ "看完就删掉购物车"
- ❌ "立即升级"
- ❌ "未来可期"

### 场景C：PPT演示

**来源**：pptx技能

**设计铁律**：
| 铁律 | 说明 |
|------|------|
| 一页一论点 | 每页只有一个核心信息 |
| 视觉层次 | 一个主色(60-70%)+1-2辅色+一个强调色 |
| 三明治结构 | 深色标题+浅色内容+深色结尾 |
| 图>表>文字 | 能用图不用表，能用表不用文字 |
| 留白呼吸 | 每页≤6行，每行≤20字 |

**配色方案**：

| 主题 | 主色 | 辅色 | 强调 |
|------|------|------|------|
| 商务汇报 | 藏青 | 冰蓝 | 白色 |
| 创业融资 | 深绿 | 苔藓灰 | 米白 |
| 产品发布 | 珊瑚红 | 金色 | 藏青 |
| 技术分享 | 炭灰 | 白炭 | 纯黑 |

**演讲者备注规范**：
- 每页备注≤50字
- 写"念什么"不写"说什么"
- 标注翻页时机

### 场景D：社交媒体

**来源**：write + viral-content-machine

**平台适配矩阵**：

| 维度 | 小红书 | 公众号 | 知乎 | 抖音 | 即刻 |
|------|--------|--------|------|------|------|
| 字数 | 300-800 | 1500-3000 | 800-5000 | 300-600 | 200-500 |
| 标题 | 关键词前置+emoji | 完整句子 | 疑问句 | 吸引眼球 | 短句+标签 |
| 段落 | ≤3行 | 2-4句 | 可长可分节 | 短句为主 | 碎片化 |
| 语气 | 亲切聊天 | 真诚有判断 | 专业有逻辑 | 强烈口语 | 洞见吐槽 |
| 互动 | 提问/投票 | 评论引导 | 点赞引导 | 挑战赛 | 互动钩子 |
| 禁忌 | 过度emoji | 模板化称呼 | 泻药体 | 长篇大论 | 空洞总结 |

**小红书专属**：
- 标题≤20字，关键词前置
- 正文300-800字，善用emoji做段落标记
- 开头直接亮点/痛点，中间干货密集，结尾互动引导

**公众号专属**：
- 标题15-30字，引发好奇或共鸣
- 开头3句定生死
- 结尾有余味或行动指引

**抖音专属**：
- 前3秒必须抓住注意力
- 每句话都要推动情绪
- 适合配音的口语化

### 场景E：Release Notes

**来源**：write技能

**核心原则**：用户可见变化导向，从git log提取。

**结构模板**：
```markdown
## Breaking Changes
## New Features
## Fixes & Improvements
## Deprecations
```

**内容规则**：
| 规则 | 说明 | 示例 |
|------|------|------|
| 按用户可见特征分组 | 不按内部功能分组 | "启动更快了" 不叫 "性能优化" |
| 从git log提取 | 不从记忆写 | 读feat:/fix:提交 |
| 一句一变化 | 不堆砌 | "App Store更新现在运行在应用内" |
| 双语结构 | 英文块+中文块并列 | 不逐条混写 |

**禁止**：
- "Polish" / "细节打磨" / "Misc improvements" — 用户看不懂
- 从记忆写 — 必须从git log/commit提取
- 一句话包含多个变化 — 拆成多条
